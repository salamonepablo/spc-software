# Common Delivery Notes — First Release

## Objective
Deliver common delivery notes only: standalone creation, creation from an existing L1 invoice, consultation, three-copy PDF, and continuation into the existing Payments circuit.

## Scope and constraints
- Keep temporary delivery notes and consignments out of scope.
- Number independently per branch for both creation routes. Invoice-originated notes start with the invoice branch, permit changing the note branch, and refresh the proposal when it changes. Never modify the source invoice's branch or number.
- Standalone stock adjustment follows the legacy opt-in/opt-out control and the salesperson-associated warehouse. Invoice-originated notes never decrement stock a second time.
- Persist header, detail, applicable stock effects, sequence, and idempotency identity atomically. Enforce branch-number uniqueness in the database and safely handle concurrent submissions/retries.
- Generate three complete, separately labeled PDF copies from saved data; opening, downloading, or reprinting must not create or mutate a note.
- Payment continuation uses the existing `/payments/new` circuit, preloaded from the source invoice (customer, original invoice branch, L1/Billing, and a reference note); do not prefill a payment amount or submit a payment automatically.
- Resolve the `IsInvoiced`/`IsVoided` column-name inversion by comparing entity, migration, and import semantics. Add a forward corrective migration; do not rewrite an applied migration or mutate historical status values without verified evidence.
- Never target production or modify VB6. Preserve pre-existing work, especially `SPC.API/bin\\Debug/` and all existing `odd/` files. The original no-commit/no-push restriction was superseded by the explicit 2026-10-02 closure authorization below. Leave the application open at the end if it is running.
- Target SQL Server database `SPC TEST` and Playwright for functional verification. Initial WSL evidence lacked API/SQL listeners and Docker CLI; Development config points to LocalDB database `SPC`. The latest verified TEST target and process-level overrides are recorded below; never use the default LocalDB configuration.

## Decisions and evidence
- Existing VB6 independent notes default stock adjustment on and use the selected salesperson's warehouse; linked-invoice notes do not deduct stock again.
- `FormImprimeRemito.BotonGrabar_Click` copies every non-empty invoice-grid row and its current quantity; the form has no partial-line/quantity editor. Exiting the form does not persist a remito or void the invoice. The .NET source flow will copy the invoice details and create no data until Save.
- Existing EF model already has `DeliveryNote`, `DeliveryNoteDetail`, invoice relation, and unique `(BranchId, DeliveryNoteNumber)` index.
- The current relationship is `DeliveryNote.InvoiceId` with the inverse `Invoice.DeliveryNotes` collection (one-to-many); do not add an unrequested one-remito-per-invoice constraint. Idempotency protects retries, while deliberate additional remitos remain possible.
- `Invoice.BranchId` exists in the entity but is omitted from API/Web invoice DTOs. Invoice-linked creation can derive it server-side when branch is absent; the Web needs the original branch to preselect it and request the branch-specific number proposal. Add `BranchId` additively to the invoice response/DTO and preserve backward compatibility.
- PDF generation: PDFsharp Core 6.2.4. Official docs confirm MIT license and cross-platform Core build: https://docs.pdfsharp.net/General/License/License.html, https://docs.pdfsharp.net/General/Overview/Choose-PDFsharp-version.html, https://docs.pdfsharp.net/General/Overview/Whats-New.html, https://www.nuget.org/packages/PdfSharp/6.2.4. Its Core font resolver throws by default on Linux; register a custom `IFontResolver` at startup and embed static Carlito regular/bold font bytes, never depend on WSL/Windows/system fonts. Official font docs: https://docs.pdfsharp.net/PDFsharp/Topics/Fonts/Font-Resolving.html and https://docs.pdfsharp.net/PDFsharp/Topics/Fonts/Sample-Font-Resolvers.html.
- Font assets: upstream `https://github.com/google/fonts/tree/main/ofl/carlito`; regular font Git blob SHA `427b95989fee609ab683d800ad00e22a4b14ecad`, bold `67543b5a1efe4b910317116b02e8e9e01659692e`, OFL license `8d6b170e4d9a5580a34471dc4ac3e8fc5fbbd712`. Preserve the copyright and `OFL.txt`; font license permits embedding/bundling, but “Carlito” is a Reserved Font Name and the fonts must not be renamed if modified.
